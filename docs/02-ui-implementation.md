# 02. UI 및 디자인 구현 지침

## 1. 디자인 목표

첨부된 감성 분석 서비스 랜딩 페이지의 시각 언어를 유지한다. 핵심은 넓은 여백, 밝은
회백색 바탕, 굵고 큰 검정 타이포그래피, 작은 상단 내비게이션, 우측 상단
이미지다. 복잡한 카드형 대시보드나 다채로운 그라데이션 UI로 바꾸지
않는다.

## 2. 참고 이미지에서 가져올 요소

-   페이지 전체 배경: 거의 흰색에 가까운 아주 옅은 회백색
-   기본 텍스트: 검정 또는 짙은 차콜
-   브랜드: 좌측 상단의 굵고 기울어진 `감성 분석 서비스` 워드마크
-   내비게이션: 상단 중앙 부근에 작은 크기의 텍스트 링크
-   주요 액션: 우측 상단 검정색 pill 형태의 `시작하기` 버튼
-   비주얼: 우측 상단의 가로형 우주/우주비행사 이미지
-   히어로: 하단에 가까운 위치에 짧은 한국어 카피와 화면 폭을 차지하는
    초대형 `SENTIMENT` 타이포그래피

이미지 파일이 준비되지 않았다면 외부 URL을 임의로 만들어 사용하지
않는다. 로컬 에셋 자리를 마련하고, 에셋이 없을 때는 깨진 이미지 대신 CSS
배경 또는 의미 있는 대체 텍스트를 사용한다.

## 3. 페이지 구성

### A. Header

-   좌측: `감성 분석 서비스` 로고
-   중앙: `플래닛은?`, `템플릿`, `둘러보기`, `자주묻는질문`
-   우측: `시작하기` 버튼
-   MVP에서 실제 페이지가 없는 메뉴는 임의의 페이지를 만들지 않는다.
    해당 섹션으로 스크롤하거나 안내용 앵커로 연결한다.
-   모바일에서는 메뉴를 단순화하되 핵심 `시작하기` 동작을 유지한다.

### B. Hero

-   짧은 소개 카피 예시:
    -   `문장 속 감정을, 가볍게 들여다보세요.`
    -   `당신의 문장에 담긴 분위기를 분석합니다.`
-   화면 아래쪽에 크게 `SENTIMENT`을 배치한다.
-   큰 글자는 화면 너비에 맞춰 유동적으로 크기를 조절한다. 모바일에서
    가로 스크롤이 생기지 않아야 한다.

### C. 분석 영역

Hero 다음 영역 또는 시작하기 버튼을 눌렀을 때 도달하는 영역으로
구성한다. - 제목: `어떤 마음이 담겨 있나요?` - 설명:
`분석하고 싶은 문장을 입력해 주세요.` - textarea - 글자 수 `0 / 2,000` -
분석 버튼 `감성 분석하기` - 짧은 개인정보 안내:
`입력한 문장은 분석 처리에만 사용되며 저장하지 않습니다.`

### D. 분석 결과

분석 성공 시 입력 영역 아래에 표시한다. - 결과 라벨: `긍정`, `부정`,
`중립` - 신뢰도: 예) `참고용 신뢰도 82%` - 분석 이유: 짧은 설명
1\~3문장 - 새 문장을 분석할 수 있는 재분석 동선 - 결과별 색상은 절제해서
사용한다. 색만으로 상태를 전달하지 않고 텍스트 라벨과 아이콘/설명을 함께
제공한다.

### E. 오류 영역

-   입력 영역과 가까운 곳에 명확하게 표시한다.
-   오류 메시지는 한국어로 작성한다.
-   원인과 사용자가 할 수 있는 행동을 짧게 안내한다.
-   오류가 생겼다고 화면 전체를 모달로 가리지 않는다.

## 4. 시각 토큰

권장 초기값이며 실제 렌더링을 확인하며 조정한다.

``` css
:root {
  --color-bg: #f7f8fa;
  --color-surface: #ffffff;
  --color-text: #080808;
  --color-muted: #777b82;
  --color-border: #dedfe3;
  --color-positive: #287a56;
  --color-negative: #b84c4c;
  --color-neutral: #666b75;

  --font-sans: "Pretendard", "Noto Sans KR", Arial, sans-serif;
  --space-page: clamp(20px, 3vw, 56px);
  --radius-control: 14px;
  --radius-pill: 999px;
  --content-max: 1200px;
}
```

폰트 파일을 무단 복사하거나 외부 CDN에 의존하지 않는다. 지정 폰트가
없으면 시스템 폰트로 자연스럽게 대체한다.

## 5. 레이아웃과 반응형

-   데스크톱: 좌우 여백이 충분한 넓은 캔버스, 콘텐츠 최대 폭 제한
-   태블릿: 헤더 간격과 히어로 타이포그래피 축소
-   모바일 360px: 내비게이션 간소화, 이미지와 텍스트 세로 배치, 입력창
    전체 폭
-   고정 높이로 주요 콘텐츠를 잘라내지 않는다.
-   `100vw`와 패딩 계산 때문에 가로 스크롤이 발생하지 않도록
    `box-sizing: border-box`를 적용한다.

## 6. 모션

-   버튼 hover/focus와 결과 등장에 짧고 절제된 전환만 사용한다.
-   분석 로딩은 작은 스피너 또는 텍스트로 표시한다.
-   `prefers-reduced-motion: reduce`를 지원한다.
-   애니메이션이 분석 결과 표시를 지연시키지 않도록 한다.

## 7. 접근성

-   모든 입력에는 연결된 label이 있어야 한다.
-   버튼은 실제 `<button>`을 사용한다.
-   포커스 표시를 제거하지 않는다.
-   오류는 `role="alert"` 또는 적절한 live region으로 전달한다.
-   결과 업데이트는 `aria-live="polite"`로 알린다.
-   텍스트와 배경의 명암 대비를 확인한다.

## 8. 완료 및 검증 기준

-   첨부 이미지와 같은 미니멀한 인상이 유지된다.
-   헤더, 히어로, 입력, 결과, 오류가 시각적으로 구분된다.
-   360px, 768px, 1440px 화면에서 가로 넘침이 없다.
-   키보드로 모든 주요 동작을 수행할 수 있다.
-   로딩/성공/오류 상태에서 레이아웃이 깨지지 않는다.
