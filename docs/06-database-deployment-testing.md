# 06. Supabase, Vercel 배포 및 테스트 지침

## 1. Supabase 사용 범위

MVP에서 Supabase는 분석 이벤트의 최소 메타데이터 저장 용도로 사용한다.
사용자가 입력한 원문 텍스트는 저장하지 않는다. 분석 기록을 조회하는
사용자 화면이나 계정 기능은 MVP 범위가 아니다.

## 2. 데이터 테이블

테이블명: `analysis_events`

  -----------------------------------------------------------------------
  컬럼                    타입                    설명
  ----------------------- ----------------------- -----------------------
  `id`                    uuid                    기본 키, 서버에서 생성

  `created_at`            timestamptz             생성 시각

  `sentiment`             text                    positive / negative /
                                                  neutral

  `confidence`            smallint                0\~100

  `processing_ms`         integer                 처리 시간(밀리초)

  `request_hash`          text, nullable          남용 탐지용 단기 해시.
                                                  원문이나 IP를 그대로
                                                  저장하지 않음
  -----------------------------------------------------------------------

원문 텍스트, 이메일, 이름, 전체 IP, API 키, 프롬프트는 저장하지 않는다.

## 3. 접근 제어

-   브라우저에서 Supabase 테이블에 직접 접근하지 않는다.
-   `SUPABASE_SERVICE_ROLE_KEY`는 서버 환경 변수로만 사용한다.
-   RLS를 활성화한다.
-   공개 `anon` 역할에 테이블 SELECT/INSERT/UPDATE/DELETE 권한을
    부여하지 않는다.
-   서버 함수만 필요한 최소 권한으로 기록한다.
-   마이그레이션 SQL과 실제 Supabase 권한을 함께 검증한다.

## 4. 보존 정책

-   분석 이벤트는 서비스 운영과 품질 점검에 필요한 기간만 보관한다.
-   초기 운영 정책은 30일 보관 후 삭제로 설정한다. 실제 자동 삭제는
    Supabase 스케줄링 또는 외부 작업으로 구현·검증해야 하며, 설정하지
    않았다면 자동 삭제된다고 문서나 UI에서 주장하지 않는다.
-   보존 기간과 개인정보 고지는 실제 운영자의 법적 검토 후 확정한다.

## 5. 환경 변수

Vercel 프로젝트 설정에 아래 변수를 등록한다. - `OPENAI_API_KEY`: OpenAI
서버 API 키 - `OPENAI_MODEL`: 실제 사용 가능한 모델 ID - `SUPABASE_URL`:
Supabase 프로젝트 URL - `SUPABASE_SERVICE_ROLE_KEY`: Supabase 서버 전용
서비스 역할 키

환경 변수는 Development / Preview / Production 환경별로 구분해 등록한다.
실제 값은 소스 코드, 문서, 스크린샷, 로그에 포함하지 않는다.

## 6. Vercel 배포

1.  Git 저장소에 프로젝트를 커밋한다.
2.  Vercel에서 저장소를 연결한다.
3.  프레임워크 프리셋은 정적 HTML/기타 적절한 설정을 선택한다.
4.  빌드 명령이 필요하지 않은 구조라면 불필요한 빌드 명령을 만들지
    않는다.
5.  Output Directory는 정적 파일 루트에 맞게 설정한다.
6.  환경 변수를 등록한다.
7.  Preview 환경에서 먼저 테스트한다.
8.  `/` 페이지와 `/api/analyze`를 확인한다.
9.  정상 확인 후 Production에 배포한다.

`vercel.json`은 필요한 경우에만 추가한다. API 경로가 정적 파일 라우팅에
가려지지 않는지 확인한다.

## 7. 테스트 계획

### 단위 테스트

-   공백 입력 거부
-   2,000자 입력 허용
-   2,001자 입력 거부
-   입력 타입 오류
-   감성 라벨 허용 목록 검사
-   confidence 정수 및 범위 검사
-   reason 빈 문자열 및 최대 길이 검사

### API 계약 테스트

-   올바른 POST 요청 성공
-   GET 요청 405
-   JSON 형식 오류 400
-   빈 입력 400
-   길이 초과 413 또는 문서화한 입력 오류
-   요청 제한 초과 429
-   OpenAI 오류 502
-   서버 설정 누락 503
-   AI 응답 스키마 오류 502

외부 API를 실제 호출하지 않는 자동 테스트에서는 OpenAI와 Supabase를 mock
처리한다. 실제 연동 스모크 테스트는 별도 환경에서 소량으로 실행한다.

### UI 수동 테스트

-   360px 모바일, 768px 태블릿, 1440px 데스크톱
-   키보드 Tab/Enter 사용
-   로딩 중 중복 클릭
-   성공 후 다른 텍스트 재분석
-   오류 후 재시도
-   스크린리더가 오류와 결과 변경을 인식하는지 확인

### 보안 점검

-   빌드 산출물에서 `OPENAI_API_KEY` 값 검색
-   브라우저 네트워크 요청에서 Supabase 서비스 키 노출 여부 확인
-   API 응답에 stack trace나 내부 설정이 없는지 확인
-   서버 로그에 입력 원문이 기록되지 않는지 확인
-   Supabase anon 역할의 테이블 접근 거부 확인

## 9. 최종 인수인계

에이전트는 구현 후 실행 명령, 환경 변수 이름, Supabase 마이그레이션 적용
방법, Vercel 배포 순서, 테스트 결과, 남은 위험 요소를 한국어로 정리한다.

주장하지 말고 사용자가 직접 해야 할 단계로 분리한다.
