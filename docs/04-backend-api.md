# 04. 백엔드 및 API 구현 지침

## 1. 책임 범위

Node.js 서버리스 API는 입력 검증, 요청 제한, OpenAI 호출, AI 응답 검증,
최소 메타데이터 저장, 오류 변환을 담당한다.

## 2. 엔드포인트

`POST /api/analyze`

### 요청

``` json
{
  "text": "입력한 문장"
}
```

### 성공 응답

``` json
{
  "ok": true,
  "data": {
    "sentiment": "positive",
    "confidence": 86,
    "reason": "긍정적인 감정을 나타내는 표현이 반복되고 있습니다."
  }
}
```

### 오류 응답

``` json
{
  "ok": false,
  "error": {
    "code": "INVALID_INPUT",
    "message": "분석할 문장을 입력해 주세요."
  }
}
```

## 3. HTTP 상태 코드

  상태   의미                                   오류 코드 예시
  ------ -------------------------------------- -----------------------
  200    분석 성공                              \-
  400    JSON 형식 또는 입력값 오류             `INVALID_INPUT`
  405    허용되지 않은 메서드                   `METHOD_NOT_ALLOWED`
  413    입력 크기 초과                         `PAYLOAD_TOO_LARGE`
  429    요청 제한 초과                         `RATE_LIMITED`
  500    내부 처리 오류                         `INTERNAL_ERROR`
  502    AI 제공자 응답 오류                    `AI_PROVIDER_ERROR`
  503    서버 설정 누락 또는 일시적 사용 불가   `SERVICE_UNAVAILABLE`

상태 코드는 실제 원인에 맞게 사용한다. 내부 오류의 스택이나 제공자 원문
메시지는 응답에 넣지 않는다.

## 4. 서버 처리 순서

1.  HTTP 메서드 확인
2.  JSON 본문 파싱
3.  `text`가 문자열인지 확인
4.  앞뒤 공백 제거
5.  빈 문자열인지 확인
6.  최대 2,000자 제한 확인
7.  요청 제한 확인
8.  서버 환경 변수 확인
9.  OpenAI 호출
10. 응답 JSON 스키마 검증
11. 허용된 값만 정규화
12. Supabase에 최소 메타데이터 저장 시도
13. 성공 응답 반환

분석 결과가 정상이라면 DB 기록 실패가 사용자 분석 자체를 실패시키지
않도록 한다. DB 기록 실패는 서버 로그에 안전하게 남기되 원문은 기록하지
않는다.

## 5. 요청 제한

-   IP 또는 익명 요청 식별값을 기반으로 기본적인 요청 제한을 적용한다.
-   서버리스 인스턴스 메모리만 사용하는 제한은 인스턴스 간 공유되지
    않음을 고려한다.
-   운영 환경에서는 공유 저장소 기반 제한 기능 또는 Vercel/외부
    게이트웨이의 제한 기능을 사용한다.
-   기본 정책값은 분당 10회로 시작하되 운영 환경에서 남용과 정상 사용을
    관찰해 조정한다.
-   제한 기준은 문서화하고 사용자에게는 잠시 후 재시도하라고 안내한다.
-   IP 전체를 장기 저장하지 않는다. 필요한 경우 단기 해시를 사용하고
    보존 기간을 제한한다.

## 6. 시간 제한 및 재시도

-   외부 API 호출에는 타임아웃을 둔다.
-   일시적인 오류에 한해 제한된 횟수로 재시도한다.
-   무한 재시도는 금지한다.
-   Vercel 함수 실행 시간보다 충분히 짧은 타임아웃을 설정한다.
-   클라이언트 취소가 서버 측 OpenAI 작업 취소를 항상 보장한다고
    가정하지 않는다.

## 7. 보안

-   OpenAI 키와 Supabase 서비스 키는 서버 환경 변수로만 읽는다.
-   요청 본문 크기를 제한한다.
-   허용되지 않은 HTTP 메서드는 거부한다.
-   CORS는 동일 출처 배포를 기본으로 하며, 별도 출처가 필요한 경우 허용
    도메인을 명시한다.
-   원문 텍스트, API 키, 서비스 키, 전체 프롬프트를 로그에 남기지
    않는다.
-   에러 메시지에서 내부 파일 경로, 스택, 계정 정보를 제거한다.

## 8. 오류 메시지 예시

-   `INVALID_INPUT`: `분석할 문장을 입력해 주세요.`
-   `PAYLOAD_TOO_LARGE`:
    `문장이 너무 길어요. 2,000자 이내로 입력해 주세요.`
-   `RATE_LIMITED`: `요청이 잠시 많아요. 잠시 후 다시 시도해 주세요.`
-   `AI_PROVIDER_ERROR`:
    `분석 서비스와 연결하지 못했어요. 잠시 후 다시 시도해 주세요.`
-   `SERVICE_UNAVAILABLE`:
    `서비스 설정을 확인 중이에요. 잠시 후 다시 이용해 주세요.`
-   `INTERNAL_ERROR`: `일시적인 오류가 발생했어요. 다시 시도해 주세요.`

## 9. 완료 및 검증 기준

-   성공/실패 응답이 문서의 JSON 계약과 일치한다.
-   잘못된 입력과 메서드를 서버에서 차단한다.
-   OpenAI 호출은 서버에서만 수행한다.
-   잘못된 AI 응답을 성공으로 반환하지 않는다.
-   API 키와 원문 텍스트가 로그/응답에 포함되지 않는다.
-   제한 초과, 타임아웃, 제공자 오류를 테스트할 수 있다.
